# Auth Lab Implementation Plan

Goal: a runnable localhost teaching demo of four auth responsibilities.

Architecture: ASP.NET Core minimal HTTP endpoints, a framework authentication handler, synchronized per-browser in-memory lab state, static Vietnamese UI. Native inline execution as requested; no worktree, agent rounds or commits.

Spec: ../specs/2026-11-17-auth-lab-design.md

## Tasks
- [x] Write HTTP integration tests with a child server on a dedicated test port; confirm failure before implementation.
- [x] Implement `Auth/demo/AuthLab.csproj`, `LabState.cs`, `Program.cs`: real random access/refresh tokens, hashed password, server role union, business rules, revoke/reset, isolation and request guards.
- [x] Implement `wwwroot/index.html`, `app.css`, `app.js`: four-part presenter navigation, actual client A/B calls, role picks, decision explanations, request trace, responsive and accessible controls.

## Review focus
All role subsets; missing/expired/copied/revoked token; refresh reuse; role changes while authenticated; reset and browser isolation; overlapping UI operations and clear business/auth distinctions.

## Implementation notes
- Opaque tokens deliberately avoid tying bearer behavior to JWT formatting. Refresh rotation invalidates the used refresh token.
- In-memory demo state expires when process ends; presenter controls are a local teaching harness.
